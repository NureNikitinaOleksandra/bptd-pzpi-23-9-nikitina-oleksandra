	Оригінальне завдання 3

	2.3 Хід вирішення
	Для виконання цього завдання я вирішила не використовувати складні бекенд-сервери, а написати повноцінний веб-застосунок (Single Page Application) в одному файлі caesar_pz2.html. Уся логіка реалізована на мові JavaScript, а для побудови графіків використана бібліотека Chart.js. Такий підхід дозволяє запускати програму локально в будь-якому браузері без додаткових налаштувань.
	Я передбачила український та англійський алфавіти, введення ключа, обробку тексту й завантаження результатів у .txt. Повного перебору всіх ключів немає.
	Роботу програми можна розділити на два великі блоки: штатний режим (шифрування/дешифрування) та режим хакерської атаки.
	Повністю весь код міститься на гітхабі за посиланням: https://github.com/NureNikitinaOleksandra/bptd-pzpi-23-9-nikitina-oleksandra.git

	2.3.1. Реалізація базового шифру Цезаря
Щоб не дублювати код для шифрування і дешифрування, я написала одну універсальну функцію transformCaesar(text, shift, alphabet):
function transformCaesar(text, shift, alphabet) {
        const lowerAlphabet = alphabet.toLowerCase();
        const upperAlphabet = alphabet.toUpperCase();
        const normalizedShift = normalizeShift(shift, alphabet.length);
        let result = "";

        for (const char of text) {
          const lowerIndex = lowerAlphabet.indexOf(char);
          if (lowerIndex !== -1) {
            result +=
              lowerAlphabet[(lowerIndex + normalizedShift) % alphabet.length];
            continue;
          }

          const upperIndex = upperAlphabet.indexOf(char);
          if (upperIndex !== -1) {
            result +=
              upperAlphabet[(upperIndex + normalizedShift) % alphabet.length];
            continue;
          }

          result += char;
        }

        return result;
      }

Її логіка дуже проста:
• Якщо ми шифруємо текст, ми передаємо позитивне значення зсуву (наприклад, +3).
• Якщо ми розшифровуємо, ми передаємо негативне значення (наприклад, -3).
Функція проходить по кожному символу тексту. Якщо це літера з нашого алфавіту, вона вираховує її новий індекс за допомогою модульної арифметики: (поточний_індекс + зсув) % довжина_алфавіту. 
Для кожної мови діє свій діапазон ключів: для української – від 0 до 32, для англійської – від 0 до 25. Регістр літер зберігається, а пробіли, цифри, пунктуація, посилання, адреси електронної пошти та інші символи, яких немає в обраному алфавіті, не змінюються.

	2.3.2. Реалізація частотної атаки
	Я реалізувала автоматизований злом шифротексту без відомого ключа за таким алгоритмом:
1. Програма зчитує зашифрований файл і рахує, скільки разів зустрічається кожна літера. Результат виводиться на екран у вигляді стовпчастої діаграми, відсортованої за спаданням.
2. Далі програма бере 4 найпопулярніші літери з шифротексту і порівнює їх з 4 еталонними найпопулярнішими літерами мови (наприклад, для української це «О», «А», «Н», «И»). Будується таблиця 4х4, де в кожній клітинці вираховується математична відстань (зсув) між літерами.
3. Якщо якийсь зсув зустрічається в матриці 2 або більше разів, програма вважає його «пріоритетною гіпотезою». Тобто ми не перебираємо всі 33 варіанти ключа всліпу, а тестуємо лише статистично обґрунтовані.
4. Програма бере відібрані ключі-гіпотези, розшифровує кожним із них невеликий фрагмент тексту (до 3000 символів) і нараховує бали за 100бальною шкалою:
• До 60 балів дається, якщо в тексті знайдено типові слова-маркери (наприклад: і, в, на, що, the, to). Я шукаю їх через регулярні вирази з повною токенізацією слів.
• До 40 балів дається за природний баланс голосних. Наприклад, в українській мові голосних має бути близько 42%. Чим ближче фрагмент до цього ідеалу, тим вищий бал.
5. Ключ, фрагмент якого набрав найбільше балів і перетнув поріг надійності, визнається переможцем. Програма остаточно дешифрує весь файл і пропонує його завантажити. Для зручності у вікні показується лише перші 500 символів розшифрованого результату.

	2.4.5 Перевірка різної кількості гіпотез
Щоб показати, що матриця може формувати різну кількість кандидатів, були використані окремо підготовлені тестові пари з великою кількістю символів. У цих файлах перші 3600 символів є зв’язним текстом, а далі йде спеціально сформований статистичний блок, який контролює частоти чотирьох найпопулярніших літер. Це зроблено саме для демонстрації, а не як приклад звичайного природного тексту.

У тесті з трьома гіпотезами отримано ключі 7, 8 і 23 (див. рис. 2.11). Їхні кількості повторень у матриці становили відповідно 3, 2 і 2. Оцінки після ранжування: 98,0 для ключа 7; 27,3 для ключа 23 і 20,4 для ключа 8. Найкращим став ключ 7, рівень впевненості – високий.

	2.5 Висновки
У результаті роботи було створено програму для шифрування й дешифрування тексту шифром Цезаря та для спроби його злому за частотним аналізом. Програма працює з українським і англійським алфавітами, зберігає регістр літер і не змінює символи поза вибраним алфавітом.
Під час атаки програма будує графік і матрицю зсувів, а потім перевіряє лише ті ключі, які повторилися щонайменше двічі. Евристика допомагає порівняти кандидатів, але не гарантує правильний результат для будь-якого тексту. Тестові файли дали змогу перевірити звичайні сценарії, граничні значення, помилкові входи та великий текст.
